# 09. 위험 관리

## 1. 평가 기준

- 발생 가능성: 낮음 / 중간 / 높음
- 영향: 낮음 / 중간 / 높음
- 위험은 주 2회 검토하며, 조기 경보가 발생하면 일정 또는 범위를 즉시 조정한다.

## 2. 핵심 위험 목록

| ID | 위험 | 가능성 | 영향 | 조기 경보 |
|---|---|---|---|---|
| R-01 | 새벽 준비가 영업 흐름을 끊음 | 높음 | 높음 | 평균 2분 초과, 테스트 5명 중 3명 이상이 반복 피로 언급 |
| R-02 | 4방향 프리렌더 에셋량 폭증 | 높음 | 높음 | 캐릭터 1종 완성에 2일 이상, 운반 동작을 별도 제작하려 함 |
| R-03 | 직접 이동이나 카메라 조작이 둔하고 피곤함 | 중간 | 높음 | 첫 접시 30초 초과, 목표 지점을 지나침, 드래그가 UI 입력과 충돌 |
| R-04 | 손님·직원 이동이 막힘 | 중간 | 높음 | 10분 플레이 중 한 번이라도 영구 정지 |
| R-05 | 경제 소프트락 | 중간 | 높음 | 다음 날 최소 재료를 살 수 없음 |
| R-06 | 영업과 준비가 서로 다른 게임처럼 보임 | 중간 | 높음 | 구매량과 판매량의 관계를 설명하지 못함 |
| R-07 | 화면 모티브가 모방으로 보임 | 중간 | 높음 | 레이아웃·색·아이콘이 특정 게임과 나란히 놓았을 때 유사 |
| R-08 | 화면이 작거나 카메라 밖이라 상태를 읽기 어려움 | 중간 | 중간 | 고등어·계란 주문을 혼동, 패드를 놓침, 필수 시설을 찾지 못함 |
| R-09 | 범위가 Stage 01 밖으로 증가 | 높음 | 높음 | 새 메뉴·손님·직원 요청이 스프린트에 포함 |
| R-10 | 저장 단계가 꼬임 | 중간 | 높음 | 구매 중 종료 후 중복 지급 또는 재료 소실 |
| R-11 | 수치 조정이 하드코딩에 묶임 | 중간 | 중간 | 비용 변경마다 여러 화면 수정 필요 |
| R-12 | 시대 배경이 어렵거나 낯섦 | 낮음 | 중간 | 이용자가 가판·화폐·시설 역할을 이해하지 못함 |

## 3. 대응 계획

### R-01 새벽 준비 반복 피로

**예방**

- 개별 재료가 아니라 5인분 묶음을 한 번에 처리한다.
- 구매와 손질 전체 목표를 60~90초로 잡는다.
- 첫날에는 준비 파트를 보여주지 않는다.
- 같은 작업대 왕복을 한 배치당 한 번으로 제한한다.

**대응**

- 손질 단계를 `운반 → 작업 → 보관`의 3단계 이하로 축소한다.
- 이미 완료한 작업을 다음 날 한 번에 처리하는 빠른 준비 기능은 Stage 01 완료 후 후보로 검토한다.

### R-02 에셋 제작량 폭증

**예방**

- 4방향은 이동 캐릭터의 대기·걷기에 우선 적용한다.
- 앉기·먹기는 좌석 방향만 제작한다.
- 운반물은 별도 부착 스프라이트로 재사용한다.
- 손님 변형은 모델 추가보다 색상 변형을 우선한다.

**대응**

- 손님 체형 B를 색상 변형으로 대체한다.
- 환경 장식 수를 줄인다.
- 최종 효과 일부는 Godot의 단순 2D 효과로 대체한다.

### R-03 이동 피로

**예방**

- 첫 화면에서 주요 동선 길이를 짧게 유지한다.
- 상호작용 범위를 시각적 시설보다 조금 넓게 잡는다.
- 방향 버튼의 크기와 길게 누르기 반응, 카메라 드래그 임계값을 실제 기기에서 조정한다.
- 이동 버튼과 카메라 드래그가 서로 다른 터치 포인터를 독립적으로 소비하게 한다.

**대응**

- 자동 달리기나 탭 이동을 추가하기 전에 이동 속도, 버튼 반응, 카메라 경계, 충돌체, 시설 배치를 먼저 수정한다.
- 같은 동선을 세 번 이상 왕복하는 작업을 줄인다.

### R-04 AI 진행 불능

**예방**

- 손님 경로와 직원 경로를 가능한 한 교차시키지 않는다.
- 좌석마다 명확한 접근 위치를 한 개만 둔다.
- 대기열 최대 인원을 3명으로 제한한다.

**대응**

- 일정 시간 이동하지 못한 캐릭터를 마지막 안전 지점으로 되돌린다.
- 오류가 발생한 손님을 안전하게 퇴장시키고 좌석과 주문을 반납한다.

### R-05 경제 소프트락

**예방**

- 영업 중 10문의 다음 날 운영자금을 보호한다.
- 시장 구매 완료 전 전액 되돌리기를 제공한다.
- 재료 소진 시 조기 마감할 수 있다.

**대응**

- 저장 데이터에서 시작 가능한 최소 재료가 없고 돈도 부족하면 5접시용 기본 꾸러미를 한 번 지급하고 로그에 남긴다.
- 반복 발생 시 비용을 낮추고 보호 규칙을 재검토한다.

### R-06 두 루프의 분리감

**예방**

- 정산에서 어제 판매량과 폐기량을 바로 보여준다.
- 시장에서 오늘 예상 손님을 보여준다.
- 구매한 인분과 영업 HUD 재고 숫자를 동일하게 유지한다.

**대응**

- 준비 완료 직후 `오늘 판매 가능 20접시` 요약을 표시한다.
- 품절 또는 폐기 순간에 원인을 짧게 설명한다.

### R-07 모방·브랜드 위험

**예방**

- 참고 대상의 상호작용 원리만 사용한다.
- 캐릭터 비례, UI 모양, 아이콘, 색 구성, 가게 배치, 애니메이션을 새로 만든다.
- Street만의 새벽 시장, 손질, 강가 가판 성장 연출을 화면 중심에 둔다.

**대응**

- 나란히 비교했을 때 고유 표현이 유사한 요소는 교체한다.
- 특정 게임의 스크린샷을 그대로 트레이싱하거나 에셋 제작 기준으로 쓰지 않는다.

### R-08 가독성 부족

**예방**

- 음식 크기를 실제보다 130~150% 크게 표현한다.
- 주문은 색과 실루엣을 함께 다르게 한다.
- 720 × 1280 화면에서 매주 검수한다.
- Day 1 핵심 시설은 단계 시작 화면에 배치하고 HUD와 방향 버튼은 카메라와 함께 움직이지 않게 한다.

**대응**

- 장식을 삭제하고 핵심 시설 사이 간격을 넓힌다.
- 주문 아이콘과 재료 숫자 크기를 올린다.
- 단계 시작 카메라 위치와 맵 경계를 조정해 필수 동선을 먼저 보여준다.

### R-09 범위 증가

**예방**

- `07_mvp_scope.md`에 없는 기능은 제외로 취급한다.
- 콘텐츠 상한을 `05_content_list.md`에서 관리한다.
- 추가 요청은 Stage 02 백로그에 기록만 한다.

**대응**

- 신규 기능을 넣어야 한다면 같은 규모의 기존 항목을 제거한다.
- 범위 교환이 불가능하면 일정과 완료 기준을 다시 승인한다.

### R-10 저장 오류

**예방**

- 영업 시작, 정산 완료, 구매 완료, 준비 완료처럼 단계 경계에서 저장한다.
- 시장의 미확정 구매는 저장하지 않는다.
- 저장 버전 번호와 기본값을 둔다.

**대응**

- 손상 데이터는 별도 백업 후 새 게임 선택지를 제공한다.
- 중복 지급보다 마지막 확정 단계 복원을 우선한다.

### R-11 수치 변경 비용

**예방**

- 비용, 시간, 판매가, 손님 수를 한 데이터 표에서 관리한다.
- UI는 같은 데이터를 읽어 표시한다.

**대응**

- P0 종료 전에 흩어진 수치를 한 곳으로 통합한다.

### R-12 시대 배경 이해

**예방**

- 현대 기능을 시대풍 오브젝트로 바꾸되 역할 아이콘은 직관적으로 만든다.
- “문”은 첫 획득 시 `엽전`과 함께 표시한다.
- 역사 용어를 튜토리얼 학습 대상으로 만들지 않는다.

**대응**

- 이해가 낮은 용어는 보편적인 표현으로 교체한다.

## 4. 중단 조건

다음 중 하나가 발생하면 신규 콘텐츠 제작을 멈추고 핵심 루프를 수정한다.

- 5명 중 3명 이상이 첫날을 끝내기 전에 이탈
- 첫 직원 고용 후에도 자동화 차이를 인식하지 못함
- 새벽 준비가 반복 테스트에서 2분을 계속 초과
- Day 1→Day 3 반복 중 진행 불능 버그가 재현
- Stage 01 완료 중앙값이 35분을 초과
- 에셋 제작 일정이 계획보다 3근무일 이상 지연
